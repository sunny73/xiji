# 发布到微信小程序

从「代码在我电脑上跑」到「别人能在微信里搜到」，中间有四道关。
这份文档按实际顺序写，并标出**哪一关最可能卡住你**。

---

## ⚠️ 先看这个：类目资质可能是硬门槛

这是本项目最大的未知风险，**建议先解决它，再花时间做后面的部署**。

### 问题

微信的服务类目是**按主体类型白名单**的。查官方[《开放的服务类目》](https://developers.weixin.qq.com/miniprogram/product/material/)：

- **个人主体**可选类目只有：快递邮政、教育、交通、生活服务、餐饮、旅游、**工具**、商业服务、体育。
  **没有「金融业」。**
- **非个人主体（企业）**才有「金融业」，其中：
  - 金融业-证券/期货 → 需《经营证券期货业务许可证》等
  - 金融业-股票信息服务平台 → 需《增值证券投资咨询》类资质 + 《增值电信业务经营许可证》

### 对本项目的含义

「分红管家」让用户录入自己的持仓和分红记录。它到底是：

- **A. 个人记账工具** → 可归入「工具」类目，个人主体也能做
- **B. 金融信息服务** → 需要金融资质，个人主体直接做不了

判定权在审核方，**取决于小程序里呈现了什么**。以下内容会显著提高被判定为 B 的概率：

| 高风险内容 | 本项目现状 | 建议 |
|---|---|---|
| 行情、股价、实时报价 | ✅ 没有（第一版明确不做） | 保持不做 |
| 收益率、年化、复利计算 | ✅ 没有 | 保持不做 |
| 投资建议 / 推荐 / 排序 | ✅ 没有 | 保持不做 |
| 分红数据来自第三方抓取 | ✅ 没有，全靠用户手录 | **保持**，这是个重要论据 |
| 出现股票名称和代码 | ⚠️ 有（用户自己录的） | 可留，但要在简介里说明是"用户录入" |
| 打新日历 / 分红日历 | ⚠️ 有 | 可留，属于记账工具的正常功能 |

### 建议做法

1. **定位写死在「个人记账工具」**：小程序名称、简介、服务类目、审核备注，四个地方口径一致。
   简介建议：`个人投资分红记账工具，数据由用户自行录入，不提供行情、不构成投资建议。`
2. 类目选 **工具 → 记账**（若没有「记账」，退到「工具 → 效率」）。
3. 提交审核时在备注里**主动说明**："所有数据由用户手工录入，无任何行情接口或第三方数据源，
   不提供投资建议"。审核员看到这句会省很多事。
4. 小程序名称**不要**带「证券」「基金」「投资」「理财」字样。用「分红管家」「分红记账」这类词。
5. 如果审核仍判定为金融信息 → 只剩两条路：换企业主体补资质，或者做成纯本地不联网的工具。
   **这一步没有技术手段能绕过**，只能靠产品定位。

> 备案环节还有一道：官方[备案指引](https://developers.weixin.qq.com/miniprogram/product/record/guidelines)
> 里列了「互联网金融」属于**前置审批**，需要「金融监管部门审批许可文件」。
> 同样取决于你的"服务内容"怎么填 —— 填成记账工具就不触发。

## 第一关：账号与资质

1. 打开 <https://mp.weixin.qq.com/> → **立即注册** → 选「小程序」
2. 选主体类型（个人 / 企业），用对应证件完成验证
3. 登录小程序管理后台，在「开发 → 开发管理 → 开发设置」里拿到 **AppID**
4. 完善小程序信息：
   - **名称**：全平台唯一，需要审核（个人主体一年可改 2 次）
   - **头像、简介**
   - **服务类目**：见上文，选「工具 → 记账」
5. 添加**开发者**（你自己的微信号），否则开发者工具里无法上传

## 第二关：后端上线

小程序必须访问 **HTTPS** 域名，且域名要在微信后台登记。所以先把后端放到公网。

### 2.1 服务器

一台境内 Linux 云服务器（1C2G 起步就够）。**必须是境内**：域名备案要求服务器在境内。

### 2.2 域名 + 备案

要办的是**两件不同的事**，容易搞混：

| | 域名 ICP 备案 | 小程序备案 |
|---|---|---|
| 在哪办 | 服务器厂商（阿里云/腾讯云）控制台 | 微信小程序管理后台 |
| 材料 | 身份证 / 营业执照 | 个人只要身份证 |
| 时长 | 1–20 工作日 | 初审 1–2 天 + 短信核验 + 通管局 1–20 工作日 |
| 用途 | 域名能解析到境内服务器 | 小程序能发布 |

**顺序**：先买域名 → 域名备案 → 解析到服务器 → 小程序备案 → 发布。

小程序备案流程（官方原文）：
```
填写备案信息 → 平台初审(1-2工作日) → 工信部短信核验(12381，24小时内完成)
→ 通管局审核(1-20工作日) → 备案成功
```
备案号上线后会自动展示在小程序"更多资料"页，**不需要自己挂**。

### 2.3 HTTPS 证书

```bash
# 用 certbot 申请，自动续期
sudo apt install certbot
sudo certbot certonly --webroot -w /var/www/certbot -d api.你的域名.com
```

### 2.4 部署后端

仓库里的 `docker-compose.yml` 已经是**生产形态**（不带源码挂载、不带 `--reload`），
开发用的便利配置在 `docker-compose.override.yml`，显式 `-f` 指定主文件就会跳过它。

```bash
git clone <你的仓库> && cd xiji

# 生产环境变量
cp .env.example .env
vim .env      # 见下方"必须改的变量"

# 构建并启动
docker compose -f docker-compose.yml up -d --build

# 建表
docker compose -f docker-compose.yml exec -T api alembic upgrade head
```

**必须改的变量**（少一个后端就拒绝启动，这是刻意设计的）：

```bash
ENV=prod
JWT_SECRET=<python3 -c "import secrets;print(secrets.token_urlsafe(48))">
WECHAT_APPID=wx................      # 小程序后台拿
WECHAT_SECRET=<小程序后台 AppSecret>
WECHAT_MOCK=false                    # 必须关，否则任何人可伪造登录
ALLOW_DEV_LOGIN=false                # 必须关
POSTGRES_PASSWORD=<强密码>
POSTGRES_HOST_PORT=                  # 见下方"不要暴露数据库"
API_HOST_PORT=127.0.0.1:8000         # 只监听本机，公网只走 Nginx
```

启动自检会拦住配置不全的情况：

```
RuntimeError: 生产环境配置不合法：
  - JWT_SECRET 仍是默认值
  - WECHAT_MOCK=true（不会真正校验微信 code）
```

### 2.5 Nginx

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/dividend.conf
sudo vim /etc/nginx/conf.d/dividend.conf      # 改域名和证书路径
sudo nginx -t && sudo systemctl reload nginx
```

验证：

```bash
curl https://api.你的域名.com/healthz     # {"status":"ok"}
```

### 2.6 备份

数据是这个产品的全部价值，**上线第一件事就是把备份配上**：

```bash
# /etc/cron.daily/dividend-backup
docker compose -f /opt/xiji/docker-compose.yml exec -T db \
  pg_dump -U dividend dividend | gzip > /backup/dividend-$(date +%F).sql.gz
find /backup -name 'dividend-*.sql.gz' -mtime +30 -delete
```

## 第三关：小程序端配置

### 3.1 换成正式 AppID

`miniprogram/project.config.json` 里的 `appid` 改成第一步拿到的 AppID。

> 开发时用的「测试号」AppID **不能发布**，必须换成正式注册的小程序 AppID。

### 3.2 指向线上接口

`miniprogram/utils/config.js`：

```js
const ENV = 'prod'

const ENVS = {
  prod: {
    baseUrl: 'https://api.你的域名.com/api/v1',
    devOpenid: '',
    allowDevLoginFallback: false,
  },
}
```

⚠️ **`devOpenid` 必须清空、`allowDevLoginFallback` 必须为 false**。
留着的话，小程序会拿一个固定 openid 去调 `/auth/dev-login` —— 而生产环境的
`ALLOW_DEV_LOGIN=false` 会让这个接口返回 404，用户直接登录不了。
（`h5/tests` 里那条 `prod 配置不允许降级到 dev-login` 的检查就是防这个。）

### 3.3 配置 request 合法域名

小程序后台 → **开发 → 开发管理 → 开发设置 → 服务器域名**：

```
request 合法域名：https://api.你的域名.com
```

要求：
- 必须是 **HTTPS**，且证书有效（不能是自签）
- 域名必须已 **ICP 备案**
- 不能带端口、不能用 IP
- 每月可修改 5 次

### 3.4 上传代码

**方式一：开发者工具（推荐）**

1. 打开项目，确认右上角显示的是正式 AppID
2. 点 **上传**，填版本号（如 `0.1.0`）和备注
3. 到小程序后台 → **版本管理** → 能看到刚上传的版本

**方式二：命令行**

```bash
CLI=/Applications/wechatwebdevtools.app/Contents/MacOS/cli
"$CLI" upload --project /path/to/miniprogram -v 0.1.0 -d "首个版本"
```

（CLI 需要先在 设置 → 安全设置 里打开服务端口，见 [SETUP-MACOS.md](SETUP-MACOS.md)）

### 3.5 体验版自测

后台 → 版本管理 → 把上传的版本设为**体验版** → 生成体验二维码 → 用微信扫。

**这一步必须认真做**，因为开发工具和真机差异很大，重点验证：

- [ ] 真机登录流程（`wx.login` → `code2Session` → JWT）
- [ ] 所有接口能通（域名、证书、备案任一有问题都会在这里暴露）
- [ ] 新增/编辑持仓、记分红
- [ ] 下拉刷新、触底分页
- [ ] 日历翻月、统计切年份
- [ ] 网络断开时的提示是否可读
- [ ] 不同机型（小屏 / 大屏 / 刘海屏）

### 3.6 提交审核

后台 → 版本管理 → **提交审核**。

填写要点：
- **服务类目**：工具 → 记账
- **功能页面**：填主要页面的路径
- **审核备注**：主动说明（见开头"建议做法"第 3 条）
- **测试账号**：如果审核员需要登录，必须提供 —— 本产品用微信登录，
  审核员用他自己的微信登录即可看到空数据，
  **建议在备注里说明"首次登录为空数据，可自行录入测试"**，
  或者准备一个演示账号并把体验版权限给它。

审核时长：一般 1–7 个工作日。

### 3.7 发布

审核通过后 → **发布** → 全量上线。也可以选**灰度发布**（按比例放量）。

## 第四关：上线后

- [ ] **备案号**：小程序备案通过后自动展示，无需操作
- [ ] **监控**：至少配一个 `/healthz` 的外部拨测
- [ ] **日志**：`docker compose logs` 默认只落本地磁盘，要配轮转
- [ ] **备份**：确认 cron 真的跑了（`ls /backup`）
- [ ] **证书续期**：`certbot renew --dry-run` 验证一次
- [ ] **数据库端口**：确认 `55432` 没有对公网开放（`deploy/nginx.conf` 只转发 API）
- [ ] **限流**：Nginx 里配了 20r/s，观察日志按需调整
- [ ] **告警**：后端 5xx 要能看到

## 常见驳回原因（按本项目最容易踩的排）

| 驳回理由 | 触发原因 | 怎么改 |
|---|---|---|
| 类目与内容不符 | 内容像金融信息，类目报的是工具 | 见开头「类目资质」一节 |
| 缺少资质 | 被判定为金融信息服务 | 同上，或换企业主体补资质 |
| 服务未对用户可见 / 功能不完整 | 审核员登录后是空数据，以为没功能 | 备注里说明"首次登录需自行录入"，或提供带数据的演示账号 |
| 诱导分享 / 诱导关注 | 文案里有"分享给好友"之类 | 去掉 |
| 用户隐私保护指引未配置 | 收集了昵称/头像但没在后台声明 | 后台「设置 → 服务内容声明 → 用户隐私保护指引」按实际填写 |
| 未备案 | 小程序备案没走完 | 备案通过后才能发布 |

## 一张图看清顺序

```
① 注册小程序账号 → 拿 AppID
        │
        ├── ⚠️ 同时确认：类目能不能过（工具→记账）
        │
② 买域名 → 域名 ICP 备案 → 解析到服务器
        │
③ 服务器上部署后端（docker compose -f docker-compose.yml）
        │
④ Nginx + HTTPS 证书
        │
⑤ 小程序备案（微信后台，个人只要身份证）
        │
⑥ 改 AppID + baseUrl 指向线上 → 上传代码
        │
⑦ 体验版真机自测
        │
⑧ 提交审核 → 通过 → 发布
```

②③④ 和 ⑤ 可以并行做。**①里的类目确认要最先做**，它决定后面这些值不值得做。
